# 감시자들 (Watchers)

> **누가, 왜 이 법을 만들었고 헌법과 어디에서 충돌하는가.**
>
> 대한민국 국가기관의 공식 기록만으로 입법과 헌법의 관계를 추적합니다.

헌법 중심 입법감시 플랫폼의 공개 프런트엔드입니다. 모바일 우선으로 설계하고, PC 화면에서는 다열
레이아웃으로 확장됩니다.

전체 기획은 [`감시자들_웹사이트_제작서.md`](./감시자들_웹사이트_제작서.md)에 있습니다.

---

## ⚠️ 현재 데이터는 전부 예시(SAMPLE)입니다

제작서 §1.1 / §30의 절대 원칙은 **“공식 기록에 없는 사실은 사실로 표시하지 않는다”**, **“AI가 공식
FACT를 추측하여 생성하지 않는다”** 입니다.

따라서 공식 API 연동 전까지는

- 실존 의안번호·의원명·표결기록을 임의로 채워 넣지 않고,
- 가상 정당·가상 의원·가상 법안으로만 화면을 검증하며,
- 모든 레코드에 `origin: "SAMPLE"` 을 붙이고 헤더에 **“예시 데이터 — 공식 API 연동 전”** 을 상시
  노출합니다.

실데이터로 교체할 때는 `src/data/*` 만 공식 API 파이프라인 결과로 바꾸면 되도록, 화면과 데이터
계층을 분리해 두었습니다.

| 영역 | 선택 |
|---|---|
| 프레임워크 | Next.js 15 (App Router) |
| 언어 | TypeScript (strict) |
| 스타일 | Tailwind CSS v4 + CSS 변수 토큰 |
| 렌더링 | 대부분 정적 생성(SSG), 목록은 쿼리스트링 대응 |

## 구현된 화면

| 경로 | 내용 | 제작서 |
|---|---|---|
| `/` | 오늘의 입법, 헌법충돌 주요 법안, 등급 범례, 신규·시행 법률, 오늘의 시민의견 | §25, §33 |
| `/bills` | 검색 + 충돌등급·상태 필터 + 정렬 | §4 |
| `/bills/[id]` | 쉬운 요약 → FACT 박스 → 입법경과 → 발의자 → 표결 → VS 헌법 → 공식 원문 → 시민투표 → 코멘트 | §5, §6, §8, §15 |
| `/constitution` | 헌법 조항 원문 + 쉬운 설명, 핵심 원칙 | §6.1, §33 |
| `/constitution/[id]` | 조항별 관련 법안 | §33 |
| `/legislators` | 의원 목록 (대표발의/공동발의/표결 건수) | §33 |
| `/legislators/[id]` | 의원별 발의·표결 기록 | §33 |
| `/transparency` | 데이터 출처, 분석 기준, 투표 집계 방식, 정정 내역 | §28 |

### 설계에서 지킨 원칙

- **FACT / ANALYSIS / OPINION 완전 분리** — 타입 단계에서 세 객체로 나누고(`src/lib/types.ts`),
  화면에서도 색·테두리·머리표시가 다른 세 종류의 박스(`src/components/Zone.tsx`)로만 렌더링합니다.
- **표결 4분류 분리** — 찬성·반대·기권·불참을 각각 별도 배열로 보관하고, “불참은 반대로 계산하지
  않습니다” 를 화면에 명시합니다.
- **헌재 판단 전 고지** — 충돌등급이 HIGH 이하이거나 헌재 판단이 없는 법안 상세에는
  “헌법재판소에 의해 위헌으로 확정된 법률은 아닙니다.” 를 강조 표시합니다.
- **공식 원문 링크** — FACT 항목·타임라인 단계·표결에 `[공식 원문]` 버튼을 답니다.
- **모바일 우선** — 기본은 하단 탭 바 + 1열, `md` 이상에서 헤더 내비게이션, `lg` 이상에서 상세
  페이지 2열(본문 + 고정 요약 사이드바)로 확장합니다.
- **접근성** — 본문 건너뛰기 링크, `aria-pressed` / `aria-current`, 다크모드, `prefers-reduced-motion`
  대응.

## 아직 구현되지 않은 것 (제작서 기준 남은 범위)

프런트 공개 화면(Phase 1~3 UI)까지가 현재 범위입니다. 다음은 서버·운영 영역으로 별도 작업이
필요합니다.

- 공식 데이터 수집 Worker (국회의안정보 / 열린국회정보 / 국가법령정보센터 / 헌재) 및 KST 00:00 Cron — §24, §31
- DB 스키마 및 저장 (§32의 테이블), 변경이력·Audit Log — §23, §29, §32
- 본인확인 기반 인증 투표, 1인 1표, 부정투표 방지 — §9, §27
  - 현재 투표·코멘트는 **브라우저 로컬 데모**이며 화면에 그렇게 고지합니다.
- 1,000표 Trigger 파이프라인: 스냅샷 영구보존 → 보고서 생성 → 언론 10곳 알림 → 헌재 제출 검토패키지 — §10~§14
- 관리자 대시보드 `/admin` (RBAC + 2FA), Trigger Monitor, 언론 발송, 댓글 모더레이션 — §17~§22, §34
